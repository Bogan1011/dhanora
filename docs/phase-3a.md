# Phase 3A — Core financial ledger

Migration 0004_finance. Accounts: bank, cash, wallet, credit card. INR only, integer paise with API results serialized as decimal strings to avoid JavaScript precision loss. Opening balance is a snapshot at the start of the chosen date, not income. Credit card debt is negative. Record actual transactions on or after account opening, no future entries. Negative balances are allowed (overdraft/debt tracking); bank reconciliation is not implemented.

One transfer record contains source and destination and yields two opposite account movements atomically. Transfers must stay within the same personal/shared scope, are excluded from income/expense totals, and cannot reference another family. Personal accounts are visible only to their owner; family admins cannot read them. Shared accounts created by owners/admins, members may record shared transactions, viewers cannot modify shared data. Personal operations permitted for all current family members on their own accounts. Owner/admin may void shared transactions; members may void their own. Voiding preserves history. No editing or hard deletion yet. Transaction creation deduplicates retries via request UUID. Account creation is not idempotent; do not repeat after ambiguous network failure without checking balances.

Overview: current liquid balances, net credit card balance, current month income/expense/net flow, expense breakdown and most recent 100 transactions. No net worth or safe-spend estimate yet. All dates use Asia/Kolkata. The frontend is an initial working interface; custom categories, search/pagination, account editing, reconciliation and recurring obligations remain future milestones.

Test with synthetic data only: create Bank and Cash with 0 openings today; add salary 50000, groceries 1500, transfer 1000 to Cash. Bank 47500, Cash 1000, total 48500, income 50000, expenses 1500. Void expense and confirm balances update. Run alembic check and opt-in PostgreSQL tests. Use localhost over SSH as in Phase 2A.
