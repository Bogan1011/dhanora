# Phase 2B — Family invitations and membership permissions

Use the existing SSH tunnel and development-only accounts. Migration 0003_family adds hashed 24-hour, single-use invitation codes. An owner can invite admin/member/viewer; an admin can invite member/viewer only. Share the code privately with the intended recipient; possession of the code authorizes new account creation using the email entered by the inviter (email delivery/verification is not provided). Existing users must sign in as the invited account before accepting. No owner creation, removal, or transfer via membership endpoints. Revoking/removing/changing an issuer's role revokes their unused invitations. Each API checks current membership on every call. Financial authorization is a future module.

Tests: docker compose exec -T -e DHANORA_RUN_DB_TESTS=1 backend pytest -v; alembic check. Browser: invite a disposable account, copy code, sign in or use Have an invitation in a separate browser profile, accept, login, check membership and owner-only actions, then revoke/remove and verify access denied. Never use actual family emails or financial information in office testing. Membership changes do not terminate other unrelated sessions. Audit events currently record actor and event only; detailed target metadata and audit viewer are later work.
